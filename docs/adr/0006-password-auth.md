# 0006. 登入改為 email + 密碼(scrypt),取代「只驗 email 存在」

- 狀態:Accepted
- 日期:2026-08-05

## Context(當時的情境)

Phase 1 的登入只檢查 email 是否存在於 `users` 表,沒有密碼 —— 當時標為
「自用內部工具可接受」的已知限制,因為系統只在本機執行。

現在要往「線上隨時可用」走(手機在外面也能上傳),而使用者的網路介面已經被
Windows 歸類為 Public。一放上公網,**任何人猜到一個 email 就能讀取並修改公司
所有報帳單據與憑證影像**。這不是「日後加固」等級的問題,是部署前的阻擋條件。

同時要考慮這個系統的規模:使用者 2–3 人、帳號由管理者建立、沒有註冊流程、
沒有 email 寄送管道(沒有 SMTP)。任何需要寄驗證信或 OTP 的方案都會先卡在
「沒有寄信管道」這件事上。

## Decision(決定)

1. **`users` 增加 `password_hash`**,登入改為 email + 密碼。
2. **雜湊用 Node 內建的 `crypto.scrypt`**,不引入 bcrypt / argon2 套件。
   儲存格式 `scrypt$N$r$p$salt$hash`(參數寫在字串裡,日後調整成本不會讓
   舊雜湊失效)。比對用 `timingSafeEqual`。
3. **`password_hash` 為 NULL 的帳號不能登入**,錯誤訊息指引去設定密碼。
   欄位可為 NULL 是為了讓 migration 不用停機,不是為了留後門。
4. **密碼規則放 `packages/core`** 的純函式 `validatePassword`(至少 10 字、
   不得全為同一字元、不得是常見弱密碼),web 與 CLI 共用同一套判斷。
5. **雜湊實作放新的 `packages/auth`**,不放 `core`。理由:`core` 會被瀏覽器端
   bundle,一旦 import `node:crypto` 會在客戶端編譯失敗(這個坑已經在
   `packages/config` 的 `node:fs` 上踩過一次,見 conventions 第 8 節)。
6. **密碼設定走 CLI**(`pnpm user:password`),另提供 `/account` 讓使用者自己
   改密碼。不做「忘記密碼」寄信重設 —— 沒有寄信管道,管理者用 CLI 重設更直接。
7. **登入失敗一律回同一句話**(「email 或密碼不正確」),不分辨帳號是否存在;
   帳號不存在時也跑一次假雜湊比對,避免用回應時間探測帳號。

## 理由

- **scrypt 是 Node 內建且是記憶體困難函數**,對這個規模足夠;少一個原生相依套件
  就少一個跨平台編譯問題(這個專案在 Windows 開發、日後可能部署到 Linux 容器)。
- **參數寫進雜湊字串**是可演進性:未來把 N 從 2^15 調到 2^17 時,舊密碼仍然
  驗得過,使用者下次改密碼時自動升級。
- **NULL 不能登入**讓遷移是安全預設值:既有帳號在設密碼前一律進不來,
  而不是「暫時可以無密碼登入」。
- 不做 OTP / magic link:沒有寄信管道,硬做會變成半殘功能。2–3 人的規模,
  管理者用 CLI 發初始密碼是最務實的。

## Consequences(代價與收穫)

- 收穫:可以安全地部署到公網;認證邏輯可測試(密碼規則有單元測試)。
- 代價:多一個 package(`packages/auth`);既有帳號要用 CLI 設一次密碼才能登入。
- 注意:**這不等於做完所有認證加固**。仍未做的:登入嘗試次數限制(自用規模先不做,
  部署到公網後應補)、雙因素、session 主動撤銷(換 `SESSION_SECRET` 可一次全撤)。
- 注意:CLI 用引數傳密碼會留在 shell 歷史。腳本因此優先讀環境變數,
  並在說明中標註。

## 被否決的替代方案

- **維持只驗 email**:等於沒有門鎖,公網部署不可行。
- **bcrypt / argon2 套件**:更主流,但引入原生編譯相依,在 Windows 開發 +
  Linux 容器部署的組合下增加風險;scrypt 內建且對此規模足夠。
- **email magic link / OTP**:沒有 SMTP 管道,得先接一個寄信服務,
  為了 2–3 人的工具不值得。
- **交給外部身分供應商(Google 登入等)**:少了密碼管理,但把「誰能存取公司報帳
  資料」綁到外部服務與 OAuth 設定上,對自用工具是反向的複雜度。
- **把雜湊放 `packages/core`**:會讓 `node:crypto` 進入瀏覽器端編譯圖並失敗;
  已在 config 的 `node:fs` 踩過同一個坑。
